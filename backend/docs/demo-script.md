# PatchWarden — Demo Script (target: 4:30)

Rule for the whole run: never show a terminal without narrating what it is
about to prove. Judges forgive a slow demo; they do not forgive a confusing
one.

---

## 0:00–0:35 — The hook

Open on the two reports side by side on screen. Do not explain the
architecture yet.

> "These are two vulnerability reports for the same library. One is real.
> One was generated by an AI and describes a bug that does not exist. Both
> are well written. Both are confident. A maintainer has to tell them apart,
> and right now there are forty-eight thousand new vulnerabilities a year and
> most maintainers are unpaid volunteers."

Beat.

> "Ingress NGINX — the front door for a huge number of Kubernetes clusters —
> stopped receiving security patches this year because its maintainers burned
> out. This is the workflow that broke them."

## 0:35–1:05 — What PatchWarden is

One slide, four boxes: **Parse → Verify → Reproduce → Patch**.

> "PatchWarden is a triage officer built on IBM Bob 2.0. It reads the report,
> checks it against the real code, reproduces what is real, and hands the
> maintainer a pull request. It never merges anything. The human always
> decides."

## 1:05–2:00 — The slop report (the surprise)

Feed report #002 to Bob live.

Narrate while the subagents run in parallel — this is the moment to name the
Bob 2.0 features out loud, because "Application of Technology" is a scored
criterion:

> "Three subagents just started at once, each with its own clean context. One
> is checking whether the functions this report names actually exist. One is
> tracing reachability. One is checking prior art."

Land on the verdict screen:

```
VERDICT: FABRICATED
CONFIDENCE: high
EVIDENCE:
  - parse_header_sanitized() does not exist in this repository
  - no eval() call in header handling
  - X-Content-Meta header appears nowhere in the codebase
  - CVE-2024-38472 is real but describes an unrelated library
ACTION: closed with evidence; no maintainer time spent
```

> "It did not just say 'looks fake.' It cited four specific things the report
> claims that are not in the code. That is a reply a maintainer can paste."

## 2:00–3:30 — The real one (the payoff)

Feed report #001. Talk over the run.

Show, in order:
1. **Verdict CONFIRMED**, with the root cause located at a real file and line.
2. **The failing test** — run it, let it go red on screen. "This proves the
   bug is real, not that Bob believes it is real."
3. **The patch.**
4. **The same test now green.**
5. **The pull request**, with the plain-language summary and the audit trail.

> "Failing test, fix, passing test. That is the artifact. A maintainer reviews
> this in about two minutes instead of spending an evening on it."

## 3:30–4:10 — Why this is different

> "Dependabot and Snyk are scanners. They point at the problem and file more
> tickets. Every tool in this space works on the reporting side. PatchWarden
> works on the maintainer's side — the person who has to answer all of it.
> And every action is logged through BobShell, because for a security fix,
> 'an AI changed this' is not an acceptable audit trail."

## 4:10–4:30 — Close

> "Open source is in roughly ninety-five percent of commercial software. It
> is held up by people doing unpaid work in their evenings. PatchWarden gives
> them their evenings back."

## Pre-record checklist

- [ ] Repo pinned to the vulnerable version; confirm the bug is live
- [ ] Both fixtures stripped of their "team notes" sections
- [ ] Dry run end to end at least twice, timed
- [ ] Record a backup run in full — if the live agent stalls, cut to it
  rather than waiting on screen
- [ ] No API keys, tokens or personal paths visible in any terminal
- [ ] `bob_sessions/` exported and committed before you stop building
- [ ] Audio checked; a clear voice track beats a pretty screen recording
